# 🛡️ SENTINEL MESH V2 — Technical Reference Manual (Layers 1–7)

This manual provides an in-depth, layer-by-layer reference of the **Sentinel Mesh V2** cognitive Anti-Money Laundering (AML) architecture. It covers the database schemas, mathematical equations, configuration parameters, and step-by-step risk-scoring calculations for two distinct sample case studies:
1. **Raj Kumar** (Structuring and Velocity Drift Case)
2. **Sam Varghese** (Shared Infrastructure and Circular Flow Loop Case)

---

## 🗺️ High-Level Layer Architecture Overview

Sentinel Mesh V2 replaces hard-coded legacy detection systems with a config-driven, multi-layered statistical and graph-based network running natively on **Microsoft Fabric** and **Azure AI Services**.

```
  ┌────────────────────────────────────────────────────────────────────────┐
  │                      SENTINEL MESH V2 ARCHITECTURE                     │
  ├────────────────────────────────────────────────────────────────────────┤
  │  Layer 1: Data Ingestion Fabric  ──→ Fabric Eventstreams & Ingestion   │
  │  Layer 2: Unified Semantic Lakehouse ─→ Eventhouse (Hot) & Delta tables│
  │  Layer 3: IQ Ontology (Behavioral DNA) ─→ 12D Profiling & Drift        │
  │  Layer 4: Temporal Knowledge Graph ─→ Community & Centrality PageRank  │
  │  Layer 5: Cognitive Agent Swarm  ──→ 6 Typology Detection Agents       │
  │  Layer 6: Adaptive Risk Scoring  ──→ 5-Factor Score & Risk Tiers       │
  │  Layer 7: AML Copilot Integration ─→ NL-to-KQL Translation & AI SAR    │
  └────────────────────────────────────────────────────────────────────────┘
```

## 📡 Layer 1: Data Ingestion Fabric

### Ingestion Flow
Transactions are generated by the simulation engine (`data_simulator/simulator.py`) and streamed in real-time to a **Fabric Eventstream** (`es_transactions`) endpoint. The Eventstream applies in-flight transformations and routes the events to:
* **Hot Path (<2s latency)**: Ingested directly into the Fabric Eventhouse KQL Database `fact_transactions` table.
* **Warm Path (Batch)**: Written to OneLake Delta tables for cold archive and historical model training.

1. **Hot Path (Eventhouse KQL DB)**: In-memory columnar storage keeping the last 30–90 days of transaction data. Used for real-time KQL Agent Swarm detection, DNA Drift scoring, and live Copilot search.

### 3.3 Behavioral DNA Vector (12 Dimensions)
Within the ontology, every customer has a running behavioral fingerprint represented as a 12-dimensional vector:

$$\vec{V}_{DNA} = [V_{vel}, V_{amt}, V_{temp}, V_{div}, V_{chan}, V_{geo}, V_{ent}, V_{rnd}, V_{rec}, V_{bst}, V_{xbd}, V_{dev}]$$

| # | Dimension | Technical Representation | AML Feature Utility |
| :---: | :--- | :--- | :--- |
| **1** | **$V_{vel}$** (Velocity) | $\lambda = \text{Count}(Txns) / \Delta t$ | Flags sudden activity bursts. |
| **2** | **$V_{amt}$** (Amount Profile) | $\mu_{amt} = \frac{1}{n}\sum amount_i$ | Detects shifts in transacting scale. |
| **3** | **$V_{temp}$** (Temporal Pattern) | $Var(Hour \pmod{24})$ | Identifies abnormal hour operations (e.g., midnight spikes). |
| **4** | **$V_{div}$** (Diversity) | $\text{DCount}(Counterparties)$ | Identifies multi-mule dissemination networks. |
| **5** | **$V_{chan}$** (Channel Mix) | $\text{UPI/Mobile Count} / \text{Total Count}$ | Identifies shifts from cash deposits to digital routing. |
| **6** | **$V_{geo}$** (Geo-spread) | $\text{DCount}(Locations)$ | Flags geographical fragmentation. |
| **7** | **$V_{ent}$** (Amount Entropy) | $\text{StDev}(amount) / \text{Mean}(amount)$ | Differentiates uniform business transactions from variable money routing. |
| **8** | **$V_{rnd}$** (Round Ratio) | $\text{Count}(amount \% 100 == 0) / \text{Total Count}$ | Flags rounded transactions common in shell structuring. |
| **9** | **$V_{rec}$** (Recurrence) | $\text{MaxCount}(Counterparty) / \text{Total Count}$ | Measures concentration to a single entity. |
| **10**| **$V_{bst}$** (Dormancy Burst) | $\text{MaxGap}(Txns) / \text{AvgGap}(Txns)$ | Flags dormant accounts suddenly activating with rapid transactions. |
| **11**| **$V_{xbd}$** (Cross-Border) | $\text{Count}(SWIFT) / \text{Total Count}$ | Identifies international flight of funds. |
| **12**| **$V_{dev}$** (Device Switching) | $\text{DCount}(Devices) / \text{Total Count}$ | Flags account takeover or multiple mules using one account. |

### 3.4 Multi-Resolution Lookback Windows
Behavioral DNA is calculated across **5 distinct time granularities** simultaneously to detect different speeds of activity shifts:
* **1 Hour (DNA-1H)**: Used to detect rapid-fire high-velocity structuring bursts (instant smurfing).
* **24 Hours (DNA-1D)**: Used to capture daily deviations; this represents the active vector ($\vec{V}_{1D}$) in drift scoring.
* **7 Days (DNA-7D)**: Used to detect weekly cycles (business patterns vs. anomalous spikes).
* **30 Days (DNA-30D)**: Represents the default **behavioral baseline vector ($\vec{V}_{30D}$)** for standard drift comparisons.
* **90 Days (DNA-90D)**: Long-term benchmark vector used to model seasonal behavior and reset long-term trend profiles.

### 3.5 Temporal Versioning
Every computed DNA vector is written as a new historical record in the Lakehouse (`dim_behavioral_dna`):
* **Point-in-Time Queries**: Allows compliance officers to query what a customer's behavior vector was on a specific past date (essential for audit trails).
* **Trend Analysis**: Enables plotting the drift path of a customer over time to observe risk escalation from LOW to HIGH.

### 3.6 AI Entity Resolution
Using PySpark Spark jobs (`entity_resolution.py`), Sentinel Mesh resolves synthetic and duplicate identities on OneLake:
1. **Fuzzy String Comparison**: Levenshtein Distance measures customer name similarities.
2. **Infrastructure Overlap**: Intersects device identifiers (`device_id`) and IPs (`ip_address`).
3. **DNA Cosine Similarity**: Compares the 12D vectors of candidates using Cosine Similarity:
   $$\text{Similarity} = \frac{\vec{A} \cdot \vec{B}}{\|\vec{A}\| \|\vec{B}\|}$$
* Customers with name similarity $\ge 85\%$, DNA similarity $\ge 90\%$, and shared devices are automatically resolved into a single logical customer profile to prevent structured aggregation evasion.

### 3.7 Mathematical DNA Drift Score
The drift score calculates the Euclidean distance between the 1-day vector ($\vec{V}_{1D}$) and the 30-day baseline vector ($\vec{V}_{30D}$). To prevent the raw amount from dominating the other normalized dimensions (0 to 1), the amount difference is scaled by the amount normalizer $C_{norm} = 10000$:

$$\text{DNA Drift Score} (\delta) = \sqrt{(V_{vel,1D} - V_{vel,30D})^2 + \frac{(V_{amt,1D} - V_{amt,30D})^2}{C_{norm}^2} + (V_{chan,1D} - V_{chan,30D})^2 + (V_{geo,1D} - V_{geo,30D})^2 + (V_{rnd,1D} - V_{rnd,30D})^2}$$

* **Anomaly Trigger**: An alert is flagged by the Velocity agent if $\delta > 3.0$ (representing a $3\sigma$ deviation).
* **Normalization for Risk Engine ($F_3$)**: The drift score is mapped to a scale of 0–100 against a maximum limit of $10\sigma$:
  $$F_3 = \min\left(100.0, \frac{\delta}{10.0} \times 100\right)$$

## 🔗 Layer 4: Temporal Knowledge Graph & Entity Resolution

This layer tracks connections across entities to detect organized networks.

### Graph Queries
Using native KQL `make-graph` and `graph-match` capabilities, the system performs sub-second graph traversal:
* **Circular Flows**: Detects loops (e.g., Account A ➔ B ➔ C ➔ A) within a 2-hour window and amount consistency ratio $\ge 80\%$.
* **Shadow Links**: Identifies distinct customers sharing physical devices (`device_id`) or network coordinates (`ip_address`).

### Spark Graph Analytics
On a daily schedule, PySpark notebooks (`L4_graph_analysis.py`) execute graph algorithms over OneLake:
1. **Louvain Community Detection**: Partitions accounts into distinct, highly connected fraud rings (communities).
2. **PageRank Centrality**: Evaluates the network influence of each account to locate money routing hubs (mules).

### Normalizing Graph Centrality ($F_2$)
The customer's PageRank score ($PR_{cust}$) is normalized against the maximum PageRank ($PR_{max}$) observed in the community network:

$$F_2 = \min\left(100.0, \frac{PR_{cust}}{PR_{max}} \times 100\right)$$

## 🐝 Layer 5: Cognitive Agent Swarm

Six KQL-native statistical detection agents run continuously to flag specific money laundering typologies:

```
                  ┌─────────────────────────────────────┐
                  │          L5 AGENT SWARM             │
                  ├─────────────────────────────────────┤
                  │  A1: Structuring Sentinel           │
                  │  A2: Velocity Anomaly Detector      │
                  │  A3: Geo-Temporal Analyzer          │
                  │  A4: Circular Flow Tracker          │
                  │  A5: Shadow Link Discoverer         │
                  │  A6: Shell Entity Profiler          │
                  └─────────────────────────────────────┘
```

1. **Structuring Sentinel ($A_1$)**: Flags deposits structured below ₹10 Lakhs CTR limit that accumulate above it within 24 hours.
   $$\text{Confidence} = \min\left(0.99, \frac{\text{Total Cumulative Amount}}{1.5 \times \text{CTR Limit}}\right)$$
2. **Velocity Anomaly Detector ($A_2$)**: Identifies customers whose DNA Drift Score exceeds the threshold.
   $$\text{Confidence} = \min\left(0.95, \frac{\text{Drift Score }\delta}{1.8 \times \text{Drift Limit}}\right)$$
3. **Geo-Temporal Analyzer ($A_3$)**: Detects impossible travel between consecutive locations.
   $$\text{Confidence} = \min\left(0.95, 1.0 - \frac{\text{Actual Interval (mins)}}{\text{Allowed Limit (mins)}}\right)$$
4. **Circular Flow Tracker ($A_4$)**: Identifies loops from the graph queries.
   $$\text{Confidence} = \frac{\text{Min Loop Amount}}{\text{Max Loop Amount}}$$
5. **Shadow Link Discoverer ($A_5$)**: Computes shared infrastructure strength.
   $$\text{Confidence} = \min\left(1.0, \frac{\text{Shared Device/IP Count}}{\text{Max Hop Depth}}\right)$$
6. **Shell Entity Profiler ($A_6$)**: Flags high volume transfers to merchants with shell scores $\ge 0.70$.
   $$\text{Confidence} = \text{Merchant Shell Score}$$

### Swarm Consensus Output ($F_1$)
The consensus factor is the average confidence of all triggered swarm agents:

$$F_1 = \left( \frac{\sum_{i=1}^{k} \text{Confidence}_{A_i}}{k} \right) \times 100$$
*(where $k$ is the number of active triggered agents).*

## 📊 Layer 6: Adaptive Risk Scoring Engine

The risk engine computes the final composite risk score using a 5-factor weighted formula, referencing parameters from `dim_adaptive_config`:

$$\text{Composite Risk Score} = (F_1 \times w_1) + (F_2 \times w_2) + (F_3 \times w_3) + (F_4 \times w_4) + (F_5 \times w_5)$$

### Risk Weight Parameters ($w_1$ to $w_5$)
* **$w_1 = 0.35$**: Swarm Consensus Weight
* **$w_2 = 0.20$**: Graph Centrality Weight
* **$w_3 = 0.20$**: Behavioral DNA Drift Weight
* **$w_4 = 0.15$**: Historical Risk Weight
* **$w_5 = 0.10$**: PEP Watchlist Weight

### Risk Classification Tiers
* **LOW**: $0.00 \le \text{Score} \le 30.00$
* **MEDIUM**: $30.01 \le \text{Score} \le 60.00$
* **HIGH**: $60.01 \le \text{Score} \le 80.00$
* **CRITICAL**: $80.01 \le \text{Score} \le 100.00$

## 🏃 CASE STUDY 1: The Raj Kumar Case
*Customer ID: `CUST-RAJ-4892` | Name: Raj Kumar | PEP Status: False*

### 📅 Case Activity Details
Within a single day, Raj Kumar executes 6 cash deposits totaling **₹50,10,000 (₹50.1 Lakhs)** across multiple branches in Chennai:
1. **09:15** — ₹9,50,000 Cash Deposit (Branch, Koramangala)
2. **10:30** — ₹8,00,000 Cash Deposit (ATM, Indiranagar)
3. **12:00** — ₹9,90,000 Mobile Transfer to Account B (Self)
4. **14:45** — ₹7,50,000 Cash Deposit (Branch, Whitefield)
5. **16:00** — ₹8,20,000 UPI Transfer to Account C (Self)
6. **17:30** — ₹7,00,000 Cash Deposit (Branch, MG Road)

---

### 🧮 Layer-by-Layer Calculations

#### 1. Layer 3: DNA Drift Calculation ($F_3$)
* **30-Day Historical Baseline Vector ($\vec{V}_{30D}$)**:
  * Velocity Baseline ($V_{vel, 30D}$): `0.10` transactions/day (rare activity)
  * Amount Profile ($V_{amt, 30D}$): `₹50,000.00`
  * Channel Mix ($V_{chan, 30D}$): `0.00` (strictly cash/branch based)
  * Geo Spread ($V_{geo, 30D}$): `1.00` (single home branch location)
  * Round Number Ratio ($V_{rnd, 30D}$): `0.10`
* **Current 1-Day Window Vector ($\vec{V}_{1D}$)**:
  * Current Velocity ($V_{vel, 1D}$): `6.00` (6 transactions in 1 day)
  * Current Amount Profile ($V_{amt, 1D}$): $\frac{\text{₹}50,10,000}{6} = \text{₹}8,35,000.00$
  * Current Channel Mix ($V_{chan, 1D}$): $\frac{2 \text{ (Mobile+UPI)}}{6} = 0.3333$
  * Current Geo Spread ($V_{geo, 1D}$): `4.00` (transacted in 4 separate sub-locations)
  * Current Round Number Ratio ($V_{rnd, 1D}$): $\frac{5 \text{ (divisible by 100)}}{6} = 0.8333$

* **Euclidean DNA Drift Score ($\delta_{Raj}$)**:

$$\Delta V_{vel} = 6.00 - 0.10 = 5.90$$

$$\Delta V_{amt} = \frac{8,35,000 - 50,000}{10,000} = \frac{7,85,000}{10,000} = 78.50$$

$$\Delta V_{chan} = 0.3333 - 0.00 = 0.3333$$

$$\Delta V_{geo} = 4.00 - 1.00 = 3.00$$

$$\Delta V_{rnd} = 0.8333 - 0.10 = 0.7333$$

$$\delta_{Raj} = \sqrt{(5.90)^2 + (78.50)^2 + (0.3333)^2 + (3.00)^2 + (0.7333)^2}$$

$$\delta_{Raj} = \sqrt{34.81 + 6162.25 + 0.1111 + 9.00 + 0.5377}$$

$$\delta_{Raj} = \sqrt{6206.7088} = 78.782\sigma$$

* **Risk Factor Normalization ($F_3$)**:
  * Since $\delta_{Raj} = 78.782\sigma$ exceeds the maximum $10\sigma$ scaling limit:
    $$F_3 = \min\left(100.0, \frac{78.782}{10.0} \times 100\right) = 100.00\%$$

---

#### 2. Layer 4: Graph Centrality Normalization ($F_2$)
* Raj Kumar's account PageRank is calculated as $PR_{Raj} = 0.045$.
* The maximum PageRank score observed in his active community is $PR_{max} = 0.10$.
  $$F_2 = \frac{0.045}{0.10} \times 100 = 45.00\%$$

---

#### 3. Layer 5: Swarm Consensus ($F_1$)
* **Agent 1: Structuring Sentinel ($A_1$)** triggers:
  * Cumulative branch deposits are ₹50.1 Lakhs. This is split across 6 transactions, all individually below the ₹10 Lakhs threshold.
  * confidence formula:
    $$\text{Confidence}_{A1} = \min\left(0.99, \frac{50,10,000}{15,00,000}\right) = 0.99$$
* **Agent 2: Velocity Anomaly Detector ($A_2$)** triggers:
  * The drift score of $78.78\sigma$ is far above the $3.0\sigma$ boundary limit.
    $$\text{Confidence}_{A2} = \min\left(0.95, \frac{78.78}{3.0 \times 1.8}\right) = 0.95$$
* **Consensus Factor ($F_1$)**:
  * Triggered agent count $k=2$.
    $$F_1 = \left(\frac{0.99 + 0.95}{2}\right) \times 100 = 97.00\%$$

---

#### 4. Layer 6: Final Composite Score
* **Factor Inputs**:
  * Agent Swarm Consensus ($F_1$) = `97.00%`
  * Graph Centrality ($F_2$) = `45.00%`
  * DNA Drift Deviation ($F_3$) = `100.00%`
  * Historical Alerts Count ($F_4$): Raj has triggered 1 minor alert in the last 30 days.
    $$F_4 = \frac{1 \text{ alert}}{5 \text{ alert limit}} \times 100 = 20.00\%$$
  * PEP watchlist flag ($F_5$) = `0.00%` (not Politically Exposed)

* **Math Execution**:

$$\text{Risk Score} = (97.00 \times 0.35) + (45.00 \times 0.20) + (100.00 \times 0.20) + (20.00 \times 0.15) + (0.00 \times 0.10)$$

$$\text{Risk Score} = 33.95 + 9.00 + 20.00 + 3.00 + 0.00$$

$$\mathbf{\text{Composite Risk Score} = 65.95 \rightarrow \text{HIGH Risk Tier}}$$

## 🏃 CASE STUDY 2: The Sam Varghese Case
*Customer ID: `CUST-SAM-5021` | Name: Sam Varghese | PEP Status: False*

### 📅 Case Activity Details
Sam Varghese is involved in a coordinated transaction cycle (circular flow) and utilizes shared access credentials:
1. **10:00 AM** — Sam receives **₹5,00,000** via mobile transfer from Priya Sharma (`CUST-PRI-1290`).
2. **11:30 AM** — Sam transfers **₹4,99,000** via mobile app to Vikram Singh (`CUST-VIK-0881`).
3. **12:15 PM** — Vikram Singh transfers **₹4,99,000** back to Priya Sharma.
4. **Device Shared**: To execute these transactions, both Sam Varghese and Vikram Singh log into the same mobile device (`DEV-MOB-9922`) within 2 hours.

---

### 🧮 Layer-by-Layer Calculations

#### 1. Layer 3: DNA Drift Calculation ($F_3$)
* **30-Day Historical Baseline Vector ($\vec{V}_{30D}$)**:
  * Velocity Baseline ($V_{vel, 30D}$): `0.20` transactions/day
  * Amount Profile ($V_{amt, 30D}$): `₹12,500.00`
  * Channel Mix ($V_{chan, 30D}$): `0.05` (primarily transacts via physical cash deposit)
  * Geo Spread ($V_{geo, 30D}$): `1.00` (Delhi region only)
  * Round Number Ratio ($V_{rnd, 30D}$): `0.10`
* **Current 1-Day Window Vector ($\vec{V}_{1D}$)**:
  * Current Velocity ($V_{vel, 1D}$): `2.00`
  * Current Amount Profile ($V_{amt, 1D}$): $\frac{\text{₹}5,00,000 + \text{₹}4,99,000}{2} = \text{₹}4,99,500.00$
  * Current Channel Mix ($V_{chan, 1D}$): `1.00` (all transactions executed digitally via Mobile App)
  * Current Geo Spread ($V_{geo, 1D}$): `1.00` (Delhi city limits)
  * Current Round Number Ratio ($V_{rnd, 1D}$): $\frac{2 \text{ (₹5,00,000 and ₹4,99,000 are round)}}{2} = 1.00$

* **Euclidean DNA Drift Score ($\delta_{Sam}$)**:

$$\Delta V_{vel} = 2.00 - 0.20 = 1.80$$

$$\Delta V_{amt} = \frac{4,99,500 - 12,500}{10,000} = \frac{4,87,000}{10,000} = 48.70$$

$$\Delta V_{chan} = 1.00 - 0.05 = 0.95$$

$$\Delta V_{geo} = 1.00 - 1.00 = 0.00$$

$$\Delta V_{rnd} = 1.00 - 0.10 = 0.90$$

$$\delta_{Sam} = \sqrt{(1.80)^2 + (48.70)^2 + (0.95)^2 + (0.00)^2 + (0.90)^2}$$

$$\delta_{Sam} = \sqrt{3.24 + 2371.69 + 0.9025 + 0.00 + 0.81}$$

$$\delta_{Sam} = \sqrt{2376.6425} = 48.751\sigma$$
